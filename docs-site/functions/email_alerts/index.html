Alertas por correoEmail alerts

Configura Observer RMM para que te avise por correo cuando un equipo se cae o cuando falla un chequeo o una tarea. Se hace una sola vez a nivel de plataforma y luego se enruta con plantillas de alertas.

Set up Observer RMM to email you when a machine goes down or when a check or task fails. You configure it once at the platform level, then route it with alert templates.

Antes de empezar

Necesitas un usuario con acceso a Configuración global y los datos de una casilla de correo saliente (servidor SMTP): dirección, puerto, y usuario/contraseña si requiere autenticación.

Before you begin

You need a user with access to Global Settings and the details of an outgoing mailbox (SMTP server): address, port, and username/password if it requires authentication.

El proceso de alertas por correo, de un vistazoThe email alerting process at a glance

El envío de una alerta recorre tres etapas: configurar (en la consola se define el relay SMTP según protocolo y puerto —587 STARTTLS, 465 TLS implícito o 25 relay interno—, los destinatarios y las plantillas de alerta), disparar (los chequeos, tareas o políticas aplicados en el agente levantan una condición —agente caído, chequeo o tarea fallida— que el backend evalúa y resuelve contra la plantilla más específica) y enviar (el firewall perimetral permite la salida del servidor Observer RMM al smtp-relay remoto, y el SMTP entrega el correo a los administradores definidos). El diagrama muestra el recorrido completo entre el agente, el frontend y el backend.

Sending an alert goes through three stages: configure (in the console you set the SMTP relay by protocol and port —587 STARTTLS, 465 implicit TLS, or 25 internal relay—, the recipients, and the alert templates), trigger (the checks, tasks, or policies applied on the agent raise a condition —agent overdue, failed check or task— that the backend evaluates and resolves against the most specific template), and send (the perimeter firewall allows the Observer RMM server outbound to the remote smtp-relay, and SMTP delivers the email to the defined administrators). 1. Configura el servidor de correo (SMTP)1. Set up the mail server (SMTP)

Ve a Configuración → Configuración global → Alertas por correo y completa la sección Configuración SMTP:

Go to Settings → Global Settings → Email Alerts and fill in the SMTP Settings section:

  • Correo del remitente — la dirección desde la que salen las alertas (por ejemplo alerta@tu-dominio).
  • Nombre del remitente — el nombre visible del remitente (por ejemplo Observer RMM).
  • Host — el servidor SMTP de tu proveedor de correo.
  • Puerto — 587 (STARTTLS, autenticado, recomendado), 465 (SSL/TLS implícito, autenticado) o 25 (relay interno sin autenticación). Observer elige el modo automáticamente según el puerto.
  • Requiere autenticación — marca esta casilla si tu servidor pide usuario y contraseña, y complétalos abajo.
La contraseña no se vuelve a mostrar

Una vez guardada, la contraseña deja de ser legible en la consola: el campo muestra un relleno y el servidor nunca la devuelve al navegador. Puedes escribir una nueva encima —el campo se limpia al hacer clic— o quitarla con el ícono de papelera. Si guardas la configuración sin tocar el campo, la contraseña guardada se conserva. Lo mismo vale para el token de Twilio y la clave de API del asistente de IA. Los datos de conexión con MeshCentral son distintos: se definen en el despliegue del servidor y la consola sólo los muestra.

  • From email — the address alerts are sent from (for example alerts@your-domain).
  • From name — the visible sender name (for example Observer RMM).
  • Host — your mail provider's SMTP server.
  • Port — 587 (STARTTLS, authenticated, recommended), 465 (implicit SSL/TLS, authenticated), or 25 (internal relay without authentication). Observer picks the mode automatically based on the port.
  • Requires authentication — check this box if your server needs a username and password, and fill them in below.
The password is never shown again

Once saved, the password is no longer readable in the console: the field shows a placeholder and the server never sends it back to the browser. You can type a new one over it — the field clears when you click it — or remove it with the trash icon. If you save the settings without touching the field, the stored password is kept. The same applies to the Twilio token and the AI assistant API key. The MeshCentral connection details are different: they are set during server deployment and the console only displays them.

Qué puerto usar

587 (STARTTLS) es lo más común y el recomendado. 465 usa TLS implícito: el canal se cifra desde la conexión. 25 es para un relay interno sin autenticación. No necesitas indicar el modo de cifrado: Observer lo deduce del puerto.

Which port to use

587 (STARTTLS) is the most common and the recommended one. 465 uses implicit TLS: the channel is encrypted from the connection. 25 is for an internal relay without authentication. You don't need to set the encryption mode — Observer infers it from the port.

2. Agrega los destinatarios2. Add recipients

En la misma pantalla, en Destinatarios, agrega los correos que recibirán las alertas. Estos son los destinatarios por defecto: se usan cuando una plantilla de alertas no define los suyos propios.

On the same screen, under Recipients, add the addresses that will receive alerts. These are the default recipients: they're used whenever an alert template doesn't define its own.

3. Envía un correo de prueba3. Send a test email

Pulsa Guardar y probar correo. Debe llegar un mensaje con el asunto “Test from Observer RMM” y la consola mostrará “Email test ok!”. Si algo está mal, el error real (autenticación, tiempo de espera, TLS) aparece aquí mismo — no lo verás en las alertas normales.

Click Save and Test Email. A message with the subject “Test from Observer RMM” should arrive, and the console will show “Email test ok!”. If something is wrong, the actual error (authentication, timeout, TLS) appears right here — you won't see it in normal alerts.

4. Crea una plantilla de alertas4. Create an alert template

El SMTP define cómo se envía; la plantilla de alertas define qué dispara un correo y a quién. En Configuración → Gestor de alertas → Agregar:

SMTP defines how mail is sent; the alert template defines what triggers an email and who receives it. In Settings → Alerts Manager → Add:

  • Activa Correo en las condiciones que te interesan: agente caído (overdue), chequeos fallidos y/o tareas fallidas.
  • Opcional: define destinatarios y remitente propios de la plantilla (sobrescriben los globales).
  • Opcional: activa la notificación periódica (reenvío cada N días si el problema sigue) y el aviso de resuelto.
  • Asigna la plantilla como predeterminada o a un cliente, sitio o política concretos.
  • Enable Email on the conditions you care about: agent overdue, failed checks, and/or failed tasks.
  • Optional: set the template's own recipients and from address (these override the global ones).
  • Optional: enable periodic notification (resend every N days while unresolved) and the resolved notice.
  • Assign the template as the default, or to a specific client, site, or policy.

Cuando una plantilla aplica por varias vías, Observer resuelve la más específica en este orden: política + sitio, sitio, política + cliente, cliente y, por último, la plantilla predeterminada.

When more than one template could apply, Observer resolves the most specific one in this order: policy + site, site, policy + client, client, and finally the default template.

5. Activa las alertas en tus chequeos y tareas5. Turn on alerts in your checks and tasks

La plantilla define el canal, pero cada chequeo y tarea automatizada debe tener marcada su casilla de alerta por correo (y el agente, su alerta de caída). Sin esto, aunque el SMTP funcione, no saldrá correo.

The template defines the channel, but each check and automated task must have its email alert box checked (and the agent, its overdue alert). Without this, no email goes out even if SMTP works.

Cómo verificar

Fuerza una condición (detén un servicio monitoreado o deja un agente sin reportar) y confirma que llega el correo. Recuerda: un envío correcto no genera ningún registro — la evidencia es el correo recibido. Solo los envíos con error quedan registrados.

How to verify

Force a condition (stop a monitored service or let an agent stop reporting) and confirm the email arrives. Remember: a successful send produces no log entry — the evidence is the received email. Only failed sends are recorded.

¿No llega el correo?Email not arriving?

  • Vuelve a Guardar y probar correo: es la forma más rápida de ver el error real.
  • Revisa la carpeta de spam del destinatario y que la dirección esté bien escrita.
  • Confirma el puerto (587, 465 o 25) y, si usas autenticación, el usuario y la contraseña.
  • Revisa el firewall perimetral: el servidor Observer RMM debe tener permitida la salida al smtp-relay remoto por el puerto configurado. Un timeout en la prueba suele ser egreso bloqueado.
  • Verifica que la condición realmente disparó una alerta y que la casilla de correo del chequeo/tarea está activa.
  • Si la prueba funciona pero las alertas no, casi siempre es el paso 5 (casilla de correo sin marcar) o la plantilla sin asignar.
  • Run Save and Test Email again: it's the fastest way to see the actual error.
  • Check the recipient's spam folder and that the address is spelled correctly.
  • Confirm the port (587, 465, or 25) and, if using authentication, the username and password.
  • Check the perimeter firewall: the Observer RMM server must be allowed outbound to the remote smtp-relay on the configured port. A timeout in the test is usually blocked egress.
  • Make sure the condition actually raised an alert and that the check/task email box is enabled.
  • If the test works but alerts don't, it's almost always step 5 (unchecked email box) or an unassigned template.
